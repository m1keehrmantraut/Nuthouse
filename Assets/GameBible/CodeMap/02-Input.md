# 02 — Input (ввод)

Папка `Assets/Scripts/Input/`. Слой, который читает кнопки/ось и складывает «намерения» в буфер. Геймплей отсюда ничего не запускает сам — только кладёт команды; решение принимает стейт-машина.

- `InputAction.cs` `[новый]` — enum действий (`Jump/Run/Crouch/Attack/HeavyAttack/Throw/Interact/Pause`) и фаз (`Pressed/Held/Released`).
- `BufferedCommand.cs` `[новый]` — одна команда в буфере: какое действие, когда нажато, сколько живёт (TTL).
- `InputConfig.cs` `[новый, SO]` — окна буферизации в секундах (`jumpBuffer 0.12`, `attackBuffer 0.15` …). Также `heavyAttackHold 0.25` — сколько держать `Attack`, чтобы получилась тяжёлая атака. Меняется в инспекторе.
- `InputReader.cs` `[новый]` — читает Unity Input System: ось движения, удержания (Run/Crouch/Jump), события нажатий. Нажатия уходят через событие `ActionPressed`. Ближняя атака — **hold-charge**: тап `Attack` (J/ЛКМ) становится лёгкой, удержание ≥ `heavyAttackHold` → `HeavyAttack`. Решение принимается по отпусканию клавиши. Карту ввода создаёт прямо в коде (рабочая заглушка вместо `.inputactions`-ассета).
- `InputBuffer.cs` `[новый]` — очередь команд с TTL. «Глупый»: не знает про кулдауны/стамину. Повторное нажатие того же действия перезаписывает старую команду. Стейты читают его через `TryConsume`.

Пайплайн: устройство → `InputReader` → `InputBuffer` → `StateMachine` читает буфер.
Пауза здесь НЕ буферизуется — уходит напрямую в `GameEvents.PauseRequested`.
