# 08 — Что починить в редакторе Unity

Код уже исправлен. Эти шаги требуют именно редактора Unity (создать префаб, добавить компоненты, назначить слои, перетащить ссылки) — из кода их не сделать.

Порядок примерный; шаг 0 обязателен (починить «Missing Script»), шаги 1–4 — чтобы всё работало, шаг 6 — чтобы ощущалось правильно.

## 0. Снять с игрока удалённые legacy-компоненты (Missing Script в 4 сценах)
Из кода удалены `CharacterController2D`, `PlayerMovement`, `PlayerHealth`, `MeleeCombat` (и мёртвый `LegacyState`). В сценах `Game`, `Stairs`, `MainLocation`, `HomeLocation` они остались на объекте игрока как «Missing Script».
- В каждой из 4 сцен выделить игрока → в инспекторе удалить 4 компонента «Missing (Mono Script)» (движение/контроллер/здоровье/ближний бой).
- В `HomeLocation` есть UnityEvent с целью `MeleeCombat` (возле строки `m_TargetAssemblyTypeName: MeleeCombat` в сцене) — убрать этот вызов из события компонента.
- `StaminaBar`: раньше ссылался на `PlayerHealth`; теперь в поле `PlayerFacade` перетащить игрока (или автонайдётся по тегу `Player`).

## 1. Создать префаб топора (иначе бросок ничего не спавнит)
- Создать пустой GameObject → сохранить как `Assets/Prefabs/Projectiles/AxeProjectile.prefab`.
- На корень: `Rigidbody2D` (Dynamic), `SpriteRenderer` (спрайт топора), `BoxCollider2D` (НЕ триггер — для столкновения с миром), скрипт `AxeProjectile`.
- Дочерний объект `Hitbox`: `BoxCollider2D` (isTrigger) + скрипт `Hitbox` — урон-зона в полёте.
- Поставить префаб на слой `Interactable` (см. шаг 4).
- Открыть `Assets/Data/Attacks/AxeThrow.asset` → в поле `axePrefab` перетащить созданный префаб.

## 2. Добавить игроку Hurtbox (иначе игрок не получает урон от хитбоксов)
- На объекте Player — дочерний `Hurtbox`: `BoxCollider2D` (isTrigger, размер ≈ тело) + скрипт `Hurtbox`, слой, который пересекается с хитбоксами врагов.
- В `PlayerFacade` (на Player) в поле `Hurtbox` перетащить этот дочерний объект.
- Physics2D-матрица: слой Hitbox пересекается с Hurtbox.

## 3. Добавить игроку PlayerAnimatorDriver (иначе анимация не управляется новой системой)
- Добавить скрипт `PlayerAnimatorDriver` на Player (он сам найдёт Animator внизу).
- Убедиться, что `Player.controller` имеет параметры из `06-EventsAndPresentation §2` (`Speed`, `Grounded`, `IsRunning`, `IsCrouching`, `VerticalVelocity`, триггеры `Attack1..`, `ThrowAxe`, `Hit`, bool `IsDead`).
- `PlayerHealth` удалён из кода — его компонент на игроке теперь «Missing Script» (снимается в шаге 0).

## 4. Слой Interactable + интеракции (иначе подбор топора не работает)
- Project Settings → Tags and Layers: добавить слой `Interactable` (например, слот 10).
- На префабе топора (шаг 1) поставить этот слой.
- В `PlayerFacade` всех игровых сцен (`Game`, `Stairs`, `MainLocation`, `HomeLocation`) в поле `Interactable Layer` указать маску `Interactable`.
- Physics2D-матрица: `Interactable` пересекается с `Player` (для `OverlapCircle`).

## 5. Привязать потолок (опционально, чтобы присед не вставал под низким потолком)
- В `PlayerFacade` каждой сцены в поле `Ceiling Check` перетащить точку-ребёнка игрока над головой (legacy `CeilingCheck` в сцене уже есть как ребёнок) — без этого присед работает, но проверка потолка выключена.

## 6. Масштаб игрока (иначе движение/прыжок/хитбокс ощущаются сломанными)
Сейчас игрок ~14 юнитов, а конфиги под ~1–2 юнита. Варианты:
- (по спеке) Уменьшить масштаб игрока до ~1–2 юнитов: пересобрать коллайдеры, точки `GroundCheck`/`CeilingCheck`, спрайт-рендер. Тогда числа `MovementConfig` (6/10, прыжок 16) заработают как задумано.
- (быстрый стопгап, отклонение от спеки) Не трогать масштаб, а поднять числа в `MovementConfig.asset` примерно в 10 раз (walk~60, run~100, jump~160) и увеличить хитбокс в `Attack1.asset`. Быстрее довести до играбельного состояния прямо сейчас, но числа расходятся с `04 §6`.

## 7. Сервисный слой (опционально, геймплей не ломает)
- Поставить префаб `GameBootstrap` в каждую сцену → сервисы сцены/прогресса заработают; меню можно перевести с `GameProgress.Instance` на `ServiceLocator.Get<ISceneService>()`.

## 8. Тяжёлая ближняя атака (hold-charge)
Код уже это поддерживает: тап `J`/ЛКМ → лёгкая (`Attack1.asset`), удержание ≥ `heavyAttackHold` (по умолчанию 0.25 с, см. `InputConfig`) → тяжёлая (`Attack2.asset`). Нужно создать ассет и привязать:
- Создать SO: в Project правой кнопкой → Create → Nuthouse → Attack Definition; назвать `Attack2.asset`, положить в `Assets/Data/Attacks/`. Рекомендуемые значения (мощнее/дольше лёгкой): `startup 0.18`, `active 0.12`, `recovery 0.35`, `damage 80`, `knockback 8`, `hitboxSize (3.5, 1.4)`, `lungeImpulse 3`, `lockMovement 1`, `animTrigger Attack2`.
- В `Player.controller` добавить триггер `Attack2` (имя — как в поле `animTrigger` ассета) и клип/переход (пока нет арта — можно временно использовать тот же клип `Fight`). `PlayerAnimatorDriver` вызовет триггер автоматически.
- В каждой игровой сцене на `PlayerFacade` в поле `Heavy Attack` перетащить `Attack2.asset` (рядом с `Primary Attack`).
- Если тяжёлая не назначена — `AttackState` автоматически откатится на лёгкую (без ошибок).

После шагов 1–4 функции (движение, прыжок, ближняя атака, урон игроку от врагов/топора, бросок и подбор топора) работают. Шаг 8 добавляет тяжёлую ближнюю атаку. Шаг 6 — «чтобы ощущалось правильно».
