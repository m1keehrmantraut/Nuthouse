# FutureComponents — продуманные, но отложенные системы

**Правило:** ничего из этой папки НЕ реализуется и НЕ получает заготовок в коде,
пока система явно не понадобится. Это защита от оверинжиниринга.

Каждый документ описывает модель, точки внедрения в текущую архитектуру и антипаттерны.
Когда система «доходит», её документ переезжает в корень GameBible и дорабатывается.

## Очередь (по мере надобности)

| Документ | Система | Когда внедрять |
|----------|---------|----------------|
| `TimeEffects.md` | Hit Stop, Slow Motion, TimeService | После этапа 6 (враги), для «веса» ударов |
| `InputDevices.md` | Мульти-девайс, Rebinding | После вертикального среза |
| `AI-Blackboard-UtilityAI.md` | Blackboard, Sensors, Utility AI | При 2+ типах врагов |
| `ComboGraph.md` | Полный граф комбо | При ветвлениях/контекстных комбо |
| `PassiveAbilities.md` | Модификаторы статов, триггерные пассивки | При прокачке/перках |
| `ReplaySystem.md` | Запись/воспроизведение ввода | Последним, требует детерминизма |

## Связь с текущей архитектурой

Все Future-системы спроектированы так, чтобы опираться на уже заложенные точки:

- Ввод → `InputReader`/`InputBuffer` (Replay, Devices).
- События → раздельные каналы 06 (TimeEffects, AI, Passive).
- Конфиги → ScriptableObject (все).
- Физика → `CharacterMotor` (AI).

То есть внедрение любой из них — добавление кода, а не переписывание ядра.
